차곡 자동 일지 · v10

구현 범위
1차 제안의 네 가지: 자동 기록 연속성, 주유·충전 감지 보강, 자동 운행 기록, 질문 보류/재개.
기본 진입 화면은 기존 주행 동반 화면이다. 정차하거나 운행이 끝났다고 일지로 강제 전환하지 않는다.

자동 기록 연속성
- 최초 화면 실행에서 시작한 기록 설정을 보존한다. 사용자가 끄면 화면 재진입·재부팅에도 꺼진 상태를 유지한다.
- 활성화 상태에서는 START_STICKY 서비스 재생성, BOOT_COMPLETED, MY_PACKAGE_REPLACED에서 재개를 시도한다.
- 일반 읽기 권한 CAR_POWERTRAIN으로 표준 GEAR_SELECTION을 읽는다. 위치·마이크를 백그라운드 서비스에서 수집하지 않는다.
- 기록 상태를 주행 화면, 설정, 서비스 알림에서 표시한다. 속도·기어·거리·잔량의 미수신을 구분한다.
- 마지막 정상 수신 시각과 연결 공백을 저장하고 설정에서 최근 이력을 볼 수 있다.
- OS의 강제 종료/백그라운드 실행 제한을 우회하지 않는다. 시작 거절은 저장하며 사용자가 앱을 열 때 다시 연결한다. 실차의 전원/사용자 정책은 별도 확인 대상이다.

충전·주유 감지
- 최신 안정값과 이벤트 시작 기준값을 분리해 1%씩 천천히 오르는 잔량도 누적한다.
- 안정 판정 10초, 누적 증가 기준 5%p. 시작 기준값과 마지막 증가 시각을 DB에 보존한다.
- 같은 이벤트는 동일 후보를 갱신한다. 이미 확정하거나 제외한 이벤트에서 추가 비용 후보를 만들지 않는다.
- 운행 재개 또는 잔량 하락에서 이벤트를 종료한다. 상승 없이 지속되는 정차는 주유 60초, 충전 30분 후 종료로 추정한다.
- 충전 스위치/포트 열림을 실제 충전 상태로 간주하지 않는다. 이번 구현은 잔량 변화 기반 추정이며 kWh·리터·금액을 계산하지 않는다.
- 관측 공백과 장시간 충전은 추정 표시를 유지한다. 여러 실제 충전을 관측 공백만으로 구분하지 않는다.

자동 운행 기록
- 속도 절댓값 0.5m/s 초과 시 자동 시작한다. 누적 주행거리 차와 관측 이동 시간을 기록한다.
- P단·정지·UX 허용 상태가 120초 이어지면 최초 주차 관측 시각을 종료 시각으로 삼는다. 신호 대기와 짧은 P단 정차는 같은 운행으로 유지한다.
- 주행 시간은 연속 수신된 이동 구간만 합산한다. 5초 넘는 공백을 이동 시간으로 채우지 않는다.
- 5초마다 진행 상태를 보관한다. 재시작 30분 이내에는 같은 운행을 이어가고 공백을 표시한다. 30분을 넘으면 이전 관측 지점에서 종료하고 다음 이동부터 새 운행을 만든다.
- 역행·비정상적으로 큰 누적 거리 변화를 거부하고 불완전 표시를 남긴다.
- 거리 이상 판정은 속도 수신 간격이 아닌 누적 거리 관측 간격을 사용한다. 초기 연결 직후에는 재연결을 30초 유예해 첫 거리 응답을 취소하지 않는다.
- 실제 화면에서 수집된 가상 친구를 해당 운행에 연결한다. 운행은 현재 로컬 사용자별로 구분한다.
- 오늘 요약, 월별 운행 목록, 관련 날짜의 확인 대기 후보를 제공한다. 지도·경로·위치는 수집하지 않는다.

질문과 정리
- 자동 질문은 정차 중, P단 확인, 음성 이용 가능, 통화 모드가 아닐 때만 시작한다. 새 운행이 시작되면 질문을 미룬다.
- ‘나중에’/무응답/화면 이탈은 초안을 보존한다. 자동 질문은 한 주차에 한 건만 시작하며, 다음 주차 전환과 최소 60초 이후 재개할 수 있다.
- ‘오늘은 묻지 마’는 사용자별 하루 보류다. 설정/확인할 기록/주행 메뉴에서 다시 받을 수 있다.
- ‘금액 몰라’는 미입력, ‘무료’는 실제 0원으로 구분한다. 두 경우 모두 별도의 명시적 확인 후 확정한다.
- 금액을 답하다 화면을 닫거나 금액 없이 저장하기로 선택한 경우에도 확인 단계부터 이어간다.
- ‘충전한 거 아니야’ 등은 후보와 내 초안을 제외한다. 정차 화면에서는 금액 없이 기록/이어 확인/제외를 선택할 수 있다.
- 실제 음성 호출·발화 정확도와 내비 안내 시점 연동은 이 변경의 검증 범위 밖이다.

데이터 보존
SQLite 문서 스키마 v3. v2 기록을 지우지 않고 새 문서 종류와 선택 필드만 추가한다. 일반 앱 DB는 초기화하지 않는다.

검증 증거
verification.json 및 device-smoke.txt에 최종 빌드/단위/기기/재부팅 결과를 기록한다.
after/는 실제 Android View를 지정 크기로 측정·배치한 캡처다. android-evidence/는 실제 PLEOS OS 창의 캡처/녹화다.
- 최종 단위 테스트 89/89 통과. 완만한 충전, 확인 대화, 운행 경계, 공백, 거리 수신 주기, 체크포인트 보존을 포함한다.
- 최종 APK의 통합 스모크 26개 중 25개가 첫 실행에서 통과했다. 1개는 PLEOS 창 이동 중 첫 탭이 전달되지 않은 테스트 동기화 문제였다. 선택된 탭을 확인하도록 테스트를 보강한 뒤 정차 화면 4개를 모두 재검증해 통과했다.
- 초기 재연결이 첫 거리 응답을 취소하던 문제를 수정했다. 거리 수신을 확인한 뒤 출발하고 서비스 재시작 후 2분 정차 종료를 검증하는 실제 SDK 테스트가 통과했다.
- 단위 테스트는 unit-results/, 개별 재검증은 final-targeted-smoke.txt와 parked-final-rerun.txt에 보관했다. 일반 DB의 v2→v3 보존 결과는 normal-data-before/after.json에 기록한다.
- 에뮬레이터를 실제 재부팅한 뒤 앱을 열지 않고 BOOT_COMPLETED 수신, 포그라운드 서비스 복구, 재부팅 이후의 새 차량 관측 저장까지 확인했다. boot-verification.json과 boot-service.txt에 증거를 남겼다.
