# 첫 화면과 첫 실행 경험

2026-11-15 · `feature/first-run-diary-pr`

## 바뀐 흐름

- 신규 사용자는 정차 후 차량 종류를 고르고 안내를 확인한 다음 **자동 기록 시작**을 누른다. 그 전에는 기록 서비스를 시작하지 않는다.
- 기존 설치는 차량 프로필과 기록 켜짐·꺼짐 선택을 유지한다.
- 최초 권한 요청에서 마이크를 제외했다. **메뉴 → 말로 기록 확인**, 또는 일지의 **말하기 시작**에서 요청한다. 권한이 없으면 자동 음성 질문도 시작하지 않는다.
- 첫 화면은 오늘 자신의 운행 횟수·관측 거리와 확인할 기록 수를 보여 준다. 누락된 거리는 0km로 만들지 않는다.
- 정차 후 **확인할 기록 N건**을 누르면 검토 화면으로 바로 이동한다. 친구 수집은 **메뉴 → 만난 친구들**에 유지한다.
- 기록을 꺼도 정차 상태를 별도로 확인하므로 다시 켜는 메뉴에 접근할 수 있다.
- 기록을 끈 상태에서도 주행 제한이 시작되면 열린 친구 목록·메뉴·미리보기를 닫고 음성 질문을 보류한다.
- 차량 속도 권한이 없으면 **차량 권한 허용하기**를 우선 표시한다. 반복 거절로 재요청할 수 없으면 앱 설정으로 연결한다. 알림 권한 거절만으로 기록 준비를 막지 않는다.
- 사용자가 시작한 음성 질문은 마이크 권한 창이 닫힌 후 화면이 활성화되고 정차 상태가 확인되면 이어진다. 화면 재생성에도 보존하며, 권한 거절이나 사용자 변경 시 취소한다.

## 화면

실제 Android View를 Pleos 에뮬레이터에서 렌더링했다. 첫 실행 캡처는 정차 상태를 주입했고, 홈에는 운행 38.2km와 미확정 충전 후보 1건을 시연 데이터로 넣었다. 실차 주행 또는 마이크 인식 결과가 아니다.

| 첫 화면 | [320 × 800](ux-home-320x800.png) | [841 × 1210](ux-home-841x1210.png) | [1400 × 430](ux-home-1400x430.png) |

차량 선택은 체크 표시와 배경으로 구분하고, 큰 가로 창에서는 선택과 안내를 나란히 놓는다. 시작 버튼은 화면 아래에 유지하며 긴 안내는 스크롤할 수 있다.

[차량 권한 복구 화면 · 320 × 800](ux-permission-recovery-320x800.png)은 정차·권한 거절 상태를 주입해 캡처했다. 준비 미완료 안내와 권한 허용 버튼을 작은 창에서도 확인했다.

## PR 기준 검증

최신 `main`(`3343e50`)에 이번 UX 변경만 옮긴 별도 작업트리에서 앱 단위 테스트 145개와 core 테스트 78개, debug·smoke·Android 테스트 APK 빌드를 통과했다.

첫 실행·권한·기존 메뉴/음성 흐름 기기 테스트 13개가 통과했다. [PR 기기 검증 로그](pr-device.txt)

같은 APK에서 실제 마이크 권한 팝업을 허용한 뒤 질문이 이어지는 테스트 1개도 통과했다. 정차 신호는 주입했고 자동 질문은 음소거했으며, 초안이 한 번만 생성되는지 확인했다. [PR 권한 팝업 검증 로그](pr-microphone-permission.txt)

## 작업 중 검증 이력

아래 기록은 원래 작업 폴더에서 진행한 검증이다. PR 기준 결과와 구분하며 실행 간 중복 테스트를 합산하지 않는다.

- JVM 테스트 139개 통과. debug APK, smoke APK와 Android 테스트 APK 빌드 통과.
- 주행 화면, 기록 설정, 정비소 연출, 가로 배치 회귀 실행: [로그](regression.txt).
- 최종 첫 실행 테스트 5개 통과: 선택 유지, 정차 제한, 기록 요약, 실제 런처에서 시작·끄기·다시 켜기, 검토 화면 이동. [로그](first-run.txt)
- 리뷰 반영 후 권한·생명주기 테스트 6개와 첫 실행 테스트 5개, 합계 11개 통과. 기록 OFF 상태의 출발 제한, 권한 복구·알림 거절 분리, 일시 정지·화면 재생성 후 질문 재개, 거절·사용자 변경 시 요청 취소를 검증했다. [로그](review-followup.txt)
- 실제 Android 마이크 권한 팝업 테스트 1개 통과. 자동 질문을 당일 음소거하고, 메뉴에서 음성 확인을 요청한 뒤 **앱 사용 중에만 허용**을 눌러 초안이 한 번 생성되는지 확인했다. 정차 신호는 주입했으며 음성 인식은 실행하지 않았다. [로그](microphone-permission.txt) · [실제 권한 팝업](microphone-permission-dialog.png)
- 기존 음성 질문 확인·백그라운드 보류와 메뉴·창 크기 배치 회귀 테스트 2개 통과. [로그](companion-followup.txt)
- 수정 전후 코드를 서브에이전트가 다시 검토했으며 추가로 확인된 회귀 지적은 없었다.
- 중간 통합 실행은 CompanionSmokeTest 도중 Android 시스템 재시작으로 중단되었다. 해당 실행은 통과로 계산하지 않고 변경 경로 11개를 별도 재실행했다.
- 권한 팝업 검증 도중 UI 자동화 오류·차량 신호 미수신·설치 APK 불일치도 확인했다. 최종 실행은 현재 APK를 다시 설치하고 SHA-256 일치를 확인한 뒤 정차 신호와 실제 권한 UI 검증을 분리해 통과했다.
- 차량 신호를 주입하는 자동 운행·재시작 사례는 이번 실행에서 제외했다. 실제 차량과 마이크 인식은 검증하지 않았다.
- Gradle 기기 실행기의 오프라인 의존성이 없어 빌드된 APK를 ADB로 설치하고 AndroidJUnitRunner를 직접 실행했다. 테스트 앱은 `io.chagok.app.smoke`이며 일반 앱의 DB를 초기화하지 않았다.
