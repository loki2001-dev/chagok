차곡 전체 UI 점검 · v9
점검일: 2026-11-14 (개발 PC 기준)

목표
주행 동반 연출을 기본 화면으로 유지하면서, 정차 시 여는 일지·관리·설정까지 같은 가독성과 디자인 기준을 적용한다.
기존 자동차·도로·만남 일러스트는 유지한다.

발견한 문제와 수정
1. Asta Sans 가변 폰트의 기본 굵기가 300이었다. 본문 500, 버튼 600, 제목 650의 명시적인 가변 축을 가진 Android 폰트 패밀리로 교체했다. 동일 굵기 Typeface는 재사용한다.
2. 화면마다 제각각이던 색상·카드·버튼·아이콘을 공통 컴포넌트로 정리했다. 본문 22~24sp, 보조 정보 20sp, 제목 28~36sp를 주로 사용한다. 작은 창에서도 주요 숫자를 축소해 숨기지 않는다.
3. 주행거리·비용 입력칸에 값이 들어가면 무슨 숫자인지 알 수 없었다. 초안, 수정, 차량, 주기, 사용자, 공유 설정에 고정된 항목 이름을 붙였다.
4. 차량 요약은 다음 관리·이번 달 지출·확인할 기록·최근 일지 순으로 정리했다. 일지에서는 날짜, 항목, 금액, 출처를 분리했다.
5. 관리 화면의 반복된 설명을 줄이고 다음 관리 거리/날짜를 각각 표시했다. 기존의 주기 설정, 알림 끄기, 7일 미루기, 기록 추가 기능을 유지한다.
6. 비용 통계는 합계와 비교 설명의 우선순위를 높였다. 6개월 그래프는 충분한 열 너비를 확보하며, 좁은 창에서는 가로 스크롤한다. 기록이 전혀 없으면 빈 그래프 대신 안내를 보여준다.
7. 관리 도감의 큰 빈 진행 카드를 작은 목록으로 바꿔 실제 학습 내용을 앞에 배치했다.
8. 만난 친구들 화면의 12~14sp 글자를 20~24sp로 키우고 창 폭에 따라 1·2·3열로 배치했다.
9. 음성 입력은 음성·직접 입력·예시 발화로 나눴다. 사용자가 읽을 필요가 없는 SDK 백엔드 식별자는 화면에서 제거했다.
10. 플랫폼 기본 대화상자도 글꼴·버튼·색상을 맞췄다. 리포트 설정에서 저장 버튼이 밀리던 높이를 제한하고 본문을 스크롤하게 했다.
11. 날짜 선택기의 낮은 대비를 확인해 큰 숫자의 날짜 선택기로 바꾸고 주·야간 테마를 지정했다.
12. 리포트 미리보기의 시스템 기본 줄 수 제한을 제거했다. 긴 문서는 끝까지 스크롤해 읽을 수 있다. 저장 목록에는 내부 파일명 대신 생성 시각을 표시한다.

검사 범위
주행 화면, 만난 친구들, 차량 스킨과 메뉴.
차량 요약, 월별 일지와 필터, 기록 상세, 초안, 음성/직접 입력, 자동 감지 후보, 소모품 관리, 비용 통계, 더보기, 관리 도감.
기록 수정, 날짜 선택, 취소 확인, 관리 동작 메뉴, 주기 설정, 차량/사용자/공유 설정, 항목 선택, 리포트 범위/미리보기/저장 목록/저장 내용.
빈 요약·일지·통계 및 야간 통계·더보기·입력.

증거 구분
before/: 변경 전 실제 Android View 캡처 34개.
after/: 변경 후 Android View 캡처. 841dp·320dp는 지정 크기로 실제 View를 측정/배치한 화면이며, -full은 스크롤 아래 내용을 포함한다.
android-evidence/: PLEOS OS가 실제로 배치한 창의 화면과 녹화. View 크기 검사와 별도로 확인한다.
index.html: 수정 전후 비교 자료.
contrast.json: 주요 텍스트/배경 조합의 WCAG 상대 휘도 대비 계산. 검사한 조합은 5.24:1 이상이다.

검증 결과
Debug·Smoke·AndroidTest APK 빌드 성공. 단위 테스트 70개 통과.
핵심 기능 스모크 19개와 전체 UI 스모크 3개가 각각 통과했다. 최초 통합 22개 실행에서는 UI 첫 터치가 누락되어 1개가 실패했고, 테스트 진입을 보완한 뒤 UI 3개를 재실행해 통과했다. 마지막 날짜/리포트 수정 후 재실행에서도 UI 3개가 36.11초에 통과했다.
마지막 재실행 도중 화면 전환이 완료되지 않는 실행 1회는 중단했다. 앱을 종료하고 같은 APK·테스트를 다시 실행해 통과했으며, 이 실행 안정성 이슈를 제품 결함 해결로 단정하지 않는다.
PLEOS 실제 분할 창 시연을 위한 배치 검사 1개도 통과했다. 내비 왼쪽, 차곡 오른쪽 841×1210dp 창에서 요약·일지·관리·통계·주행 진입을 확인하고 35초 녹화를 남겼다.
수정 후 UI 점검 캡처 64개와 주행 스킨 장면 2개를 비교 자료에 제공한다. 최신 일반 Debug 앱을 설치하고 기본 주행 화면을 오른쪽 창에 띄워 두었다. 일반 앱 데이터를 초기화하지 않았다.
실행별 결과와 APK 지문은 verification.json 및 device-smoke.txt에 기록했다.

검증의 범위와 한계
기존 PLEOS 주행 중 NO_VIDEO 제한 처리는 바꾸지 않았다. 일반 앱은 해당 제한에서 정적 표시로 전환하며, 연출 장면 캡처는 전용 테스트 또는 정차 미리보기의 결과다.
실행 검증은 PLEOS 2.1.0 API 34 에뮬레이터에서 수행한다. 실제 차량 패널의 시인성과 물리적 음성 인식 품질은 별도 실차 확인 대상이다.
화면 이동 자동화에서는 지속되는 주행 애니메이션을 테스트 코드에서만 일시 정지한다. 연출 동작은 별도 주행 연출 테스트가 검증하며 제품 코드는 이 정지 동작을 적용하지 않는다.
리포트·데이터 변경 테스트는 io.chagok.app.smoke 전용 저장소를 사용한다. 일반 앱의 차량 일지를 초기화하지 않는다.
